# Four small routines with several callers each.

MB &4555 IS_NAME_CHAR
MB &46C2 PAGE_ON_TWO
MB &5D9F COPY_THEN_APPEND_CALL

DOC IS_NAME_CHAR
    Carry set if the character in A may appear in a name.

    It chains onto the letter-or-digit test at &454A and adds underscore,
    &5F, which the ROM's own classifier does not accept.  HK_SKIPNAME
    already described this routine from the outside -- "reads forward
    while the classifier at L4555 keeps saying the character belongs to a
    name" -- so this is the classifier that description meant.

DOC PAGE_ON_TWO
    Move the window on by two pages and turn HL into a window address.

    IN A,(HMPR), add 2, OUT, then SET 7,H.  Two pages is 32K, and the
    address is left pointing into &8000-&BFFF at the same offset.  A is
    preserved through the alternate set rather than the stack.

DOC COPY_THEN_APPEND_CALL
    Do the caller's LDIR, then append three bytes that are a CALL.

    The three bytes at &5DAB are CD 5B 4B -- CALL &4B5B -- so whatever
    was just copied is finished off with a call to that address.  It is
    another of this image's run-time code builders, and the smallest:
    the caller supplies the body, this supplies the ending.  HL is
    preserved across the appended copy so the caller still has the end of
    its own block.

MB &4240 BYTE_TO_DECIMAL
    A to three decimal characters, returned in B, C and A -- hundreds,
    tens and units.  DECIMAL_DIGIT is called with DE = 100 and then with
    DE = 10, and what is left in L is the units.  C carries the padding:
    &20 going in, so a leading zero prints as a space, and DECIMAL_DIGIT
    sets it to &30 as soon as a digit is non-zero, so the zeros after it
    print as zeros.

    Nothing in this listing calls it.

MB &425D DECIMAL_DIGIT
    One digit by repeated subtraction: take DE from HL counting in A
    until it goes negative, add DE back, and return A + &30 -- or C
    unchanged if A came out zero, which is what makes the padding above
    work.  Slower than a shift-and-subtract division and a great deal
    shorter, which for three digits is the right trade.

MB &454A IS_LETTER_OR_DIGIT
    Carry set if A is a letter or a digit.  IS_LETTER first, and a RET C
    if it was one; otherwise fall into IS_DIGIT and let its answer stand.
    IS_NAME_CHAR at &4555 is this plus whatever else a name may contain.

MB &459C SET_DCT_COMPILE_BITS
    Read DCT, OR &05, and fall into WRA to put it back -- so bits 0 and 2
    go up.  The exact complement of what HK_PROGPREP does with AND &FA
    before it rebuilds the compile pass, which is the best evidence that
    those two bits are the "needs compiling" state.

MB &4717 SAVE_FAR_POINTER
    Normalise HL through the rotating window -- BIT 6,H and INCURPAGE,
    the ROM's own step-the-page routine -- and keep the result in V409A
    with the page it belongs to in V409C.

MB &4725 COMPARE_FAR_STRINGS
    Compare against the pointer SAVE_FAR_POINTER left, byte for byte,
    with the two strings in different pages.  E holds the saved page and
    D the current one, C holds HMPR, and each byte costs two OUT (C),r:
    one to page in the saved string and read it, one to page the other
    back and compare.  The alternate registers carry the second pointer,
    so neither has to be reloaded round the loop.

MB &47E6 GET_STRING_PAGED
    Evaluate a string and hand back a paged address.  GETSTR leaves the
    page in A and an offset in DE, and if the page is not zero SET 6,D
    turns that offset into a section B address -- the same long-address
    convention LONGADDR_TO_PAGED and PAGED_TO_LONG work in.
