# OPEN, and the channel records an open file lives in.
#
# Prose for listings/clean/ only.

RENAME CHANNEL_ENTRY_AT_ZERO_PAGE END_OF_CHANNELS

GROUP Channels
CONST CHANNEL_BLOCK = &0313 : bytes in one open file's channel record
CONST CHANS_BIAS_AND_FIRST = &401E : the window bias, and past the standard channels
CONST MAX_OPEN_BLOCKS = &06 : how many blocks OPEN BLOCKS will reserve

DOC CMD_OPEN
    OPEN, in three forms.

        OPEN #s,"name" IN|OUT|RND    attach a stream to a file
        OPEN DIR "name"              make a subdirectory
        OPEN BLOCKS n                reserve n file blocks in advance

    THE THIRD IS NOT IN EITHER MANUAL this project has.  It is reached
    by the token &A9, which the ROM's tables call BLOCKS, and it takes a
    number from 1 to 6.

    WHAT IT RESERVES is n channel records of 787 bytes each, made at the
    end of the ROM's channel area and left marked unused.  Opening a
    file for real needs that space, and getting it means growing the
    channel area, which moves the program and the variables above it --
    slow, and a thing that can fail in the middle of a program that has
    already written half a file.  Reserving the blocks first turns each
    later OPEN into filling in a record that is already there.

    A RESERVED BLOCK IS RECOGNISED BY THE CHANNEL LETTER AT OFFSET 4
    being zero -- that is what the scan for a free block tests.  Offset 0
    is zeroed too, but for a different reason: it is the low byte of the
    output-routine address, and a zero there stops the record reading as
    the carriage return that ends the list.  The length at offset 9 is
    set to 787 so that anything walking the list steps over it correctly.

    787 IS NOT ARBITRARY.  A channel record holds the ROM's five-byte
    channel header, the DOS's own state, a whole 256-byte copy of the
    file's directory entry, and a 512-byte sector buffer: everything the
    DOS needs to service that file, in one block, which is what lets
    several files be open at once.

DOS &6AA0 : the BLOCKS token, which is the third form
DOS &6AA2 : anything else is a stream or a directory
DOS &6AAA : the count has to fit in a byte
DOS &6AB1 : counted from one, so compare from zero
DOS &6AB2 value MAX_OPEN_BLOCKS
DOS &6AB4 : one to six, and no more
DOS &6AB7 value CHANNEL_BLOCK
DOS &6ABC : zero, to be added to n times
DOS &6ABF : n of them, by adding rather than multiplying
DOS &6AC4 : the end of the channel list, which is where they go
DOS &6AC9 : and the ROM opens the gap
DOS &6AD2 : offset 0, so the record is not read as the end-of-list marker
DOS &6AD6 : and the letter at offset 4, which is what marks the block free
DOS &6ADA : but the length, so a walk of the list steps over it
DOS &6ADD : and its high byte
DOS &6AE0 : on to the next block
DOS &6AE4 : and MasterBASIC is told the channel area has moved

DOC OPND44
    The file exists: fill the channel record from its directory
    entry and read its first sector.

    THE WHOLE ENTRY IS COPIED INTO THE RECORD at FFSA, which is what
    makes every later offset into the entry an offset into the
    record.  The type and name go to NSTR1 as well, the first track
    and sector come out of offsets 13 and 14, and the pointer's
    sector count starts at zero so that COUNT_AND_READ_SECTOR makes
    it one as it reads.

DOS &6C0F expr ENTRY_LENGTH
DOS &6C1E expr NAME_AND_TYPE
DOS &6C2E expr CNTL
DOS &6C31 expr CNTH
DOS &6C31 : no sectors read yet

DOS &6B61 : the ROM's STREAMS table through the window: stream 0's entry is at &5C16, two bytes a stream
DOS &6B65 : the doubled stream number alone
DOS &6C57 expr TYPE_MASK
DOS &6C59 expr TYPE_OPENTYPE
DOS &6C63 : &10 and up is a SAM type, with a nine-byte header in the file
DOS &6C72 : the carry out of the add, into the top byte
DOS &6C77 : 48K, the length of a 48K snapshot's image
DOS &6C7B expr TYPE_ZX_SNP48

DOC CMD_OPEN_1
    Not BLOCKS, so a stream or a subdirectory.

    "#" is a stream, and anything else is passed to OPNDIR -- which is
    how OPEN DIR gets there without a test of its own.

DOS &6B21 : "#" introduces a stream
DOS &6B23 : anything else had better be DIR

DOC OPEX
    Refuse a stream that is already attached to something unusual.

    Streams 0 to 3 are the ROM's own and may be taken over freely; they
    are put back to their defaults when closed.  For 4 upwards, the
    displacement STRMD returns says which channel the stream points at,
    and anything past the last standard channel means the stream is
    already in use.

DOS &6B3B : where in the stream table this stream points
DOS &6B3E : streams 0 to 3 are the ROM's, and may be taken
DOS &6B42 : the last of the standard channels
DOS &6B48 : past it, so this stream is already attached to something

DOC END_OF_CHANNELS
    Find the end of the ROM's channel list, with the system page mapped.

    CHANS holds the head of the list in the ROM's own numbering, so
    &4000 is added to reach it through the window; &1E more steps past
    the standard channels to the first that could be the DOS's.  From
    there each record's own length at offset 9 says how far the next
    one is, and a carriage return where the next record's first byte
    would be is the end -- the ROM closes the list with one.

    CHKHL is the ROM's own bounds check, called before each read, so a
    corrupt length cannot walk this off into nothing.

DOS &6AEB : the system page, where the channel list is
DOS &6AED : the head of the list
DOS &6AF0 expr CHANS_BIAS_AND_FIRST
DOS &6AF4 : the ROM's window step -- past &BFFF it pages the next 16K in and drops HL back to &8000
DOS &6AF9 : offset 9 is this record's length
DOS &6AF3 END_OF_CHANNELS_LOOP
DOS &6AF7 : offset 0, which is &0D only at the end of the list
DOS &6B01 : a carriage return where a record should start is the end of the list

DOC RESET_CHANNEL_SCAN
    Walk the channel list before opening a file, and find where the
    new channel will go.

    THE 1991 SOURCE CALLS THIS OPEND, and it does three things on one
    pass.  It remembers the first reserved block it meets -- a record
    whose letter at offset 4 is zero, which is what OPEN BLOCKS leaves
    -- in TEMPW1, so that a new channel can go there instead of at the
    end.  It refuses to open a file that is open already, with
    "Channel used".  And it stops on the carriage return that closes
    the list, which is where the channel goes if no block was
    reserved.

    THE CLASH TEST IS LOOSER THAN THE SOURCE'S, in a way the source
    does not have at all.  Two checks were added in front of the name
    compare: if the file is being opened IN, FSTR1 holding MIN, there
    is no clash to look for; and if the channel already open is IN --
    the two mode bits at offset &0C both clear -- it does not count as
    a clash either.  So any number of readers may share a file, and
    only a writer or a random-access channel excludes another.

    The letter is tested under AND &5F, which folds the case and
    drops bit 7: a temporary channel is "D"+&80, and OPDST1 clears
    that bit to make one permanent.

DOS &6B78 : the system page, where the channel list is
DOS &6B7A expr TEMPW1+1
DOS &6B7A : the high byte of TEMPW1: no reserved block seen yet
DOS &6B7D : the head of the list
DOS &6B81 expr CHANS_BIAS_AND_FIRST
DOS &6B86 : offset 0, which is &0D only at the end of the list
DOS &6B89 : the carriage return that closes the list
DOS &6B8D : the channel letter, or zero for a block OPEN BLOCKS reserved
DOS &6B93 : the first reserved block is where the new channel will go
DOS &6B97 : either case, and bit 7 off: a temporary channel is "D"+&80
DOS &6B99 : a disc channel?
DOS &6BA0 expr DRIVE-DCHAN
DOS &6BA0 : on the same drive?
DOS &6BA8 expr MIN
DOS &6BAA : opening for input never clashes
DOS &6BAC expr FLAG3-DCHAN
DOS &6BAF : bits 0 and 1 are the mode: 0 IN, 1 OUT, 2 RND
DOS &6BB1 : and a channel that is reading does not clash either
DOS &6BBE : ten characters of name
DOS &6BC2 expr CASE_BLIND
DOS &6BCA : the same name, open for writing: "Channel used"
DOS &6BCD : offset 9 is this record's length
DOS &6BD0 : and offset 10 its high byte
DOS &6BDF expr DIR_MODE_NAME_ONLY
DOS &6BE1 : is there a file of that name on the disc?
DOS &6BD7 : the reserved block, if one was seen
DOS &6BDE : which replaces the end of the list as the place to build
