DOC BOOT
    Load the rest of the DOS and MasterBASIC off the disc, into a page
    found at run time, and start them.

    THE PAGING IS THE THING TO GET STRAIGHT FIRST, because every odd
    line below follows from it.  The boot sector has been read to &8000
    and jumped to, so this code is running in the window: the system
    page is low, at &4000, and this half is high.  Two consequences run
    through the whole routine.

    Writing to the ROM's variables needs no windowing at all -- FRAMIV
    at &5AE2 is simply there, at &4000-odd, which is why the second
    instruction can store to it directly.  Everywhere else in these two
    listings that would need NRRD or a window.

    Reaching this half's own data does need windowing, because the
    assembler laid it out at &40F9 and it is executing at &80F9.  That
    is the IN_PAGE_C added to every one of its own addresses here.  The
    same &4000 appears in the JP at the end of the sector loop, which is
    absolute where a JR could not reach.

    WHAT IT DOES, in four movements: reset two ROM interrupt vectors;
    sweep the page allocation table clear of RAM discs left by an
    earlier boot; find a page to load into, taking a screen if there is
    nothing better; then read the file a sector at a time, driving the
    disk controller by hand because none of the DOS's own routines
    exists yet.

    Errors: "Out of memory" if no page can be found, "Loading error"
    after ten failed attempts at one sector.

DOS &4009 step
    Interrupts off: the ROM's frame interrupt is about to be pointed at
    nothing, and the stack is about to move.

DOS &400A step
    Put the two interrupt vectors back where the ROM would have them:
    the frame interrupt off, and the general one pointing at the ROM's
    own handler.  Both are ROM variables, and the system page is low
    while this runs, so both are written without any windowing.

DOS &400A : nothing on the frame interrupt
DOS &4010 : H is still zero, so HL becomes ANYI, the ROM's own handler

DOS &4012 : the any-interrupt vector, which the ROM checks before its own

DOS &4015 expr ALLOCT + MAX_INTERNAL_PAGE
DOS &4015 : the top entry of the page allocation table

DOS &4015 step

    earlier boot.  Their pages are still marked as belonging to a DOS
    that is no longer running, and nothing else will ever free them.

DOS &401B : below the range: not a RAM disc
DOS &401F : above it: not a RAM disc either
DOS &4021 : a RAM disc from a previous boot -- give the page back

DOS &4023 step

    zero is the system page and is never a candidate.

DOS &4026 step

DOS &4026 : which page is in the window -- the one holding this code
DOS &402B : start one below it

DOS &402C step

    this half's own address and this half is at &8000.

DOS &402C : saved where this half can find it again

DOS &4033 step
    Look for a page to put the DOS in: a free one for preference, a
    screen page if there is nothing else, working down to the system
    page.  H has not been touched since &4015, so HL is still an entry
    in the allocation table.

DOS &4034 : zero means the page is free
DOS &4037 : a screen will do -- it can be taken back
DOS &403C : keep going down; zero is the system page and stops the scan
DOS &403E : nothing free and no screen to take

DOS &4040 step
    A page has been found.  Now read the file, following the chain of
    sector addresses each sector carries in its last four bytes.  The
    first wave is the DOS itself.

DOS &4041 : the last two bytes of the boot sector, in this half

DOS &4049 step
    One sector.  Everything from here to the end drives the WD1772
    directly: none of the DOS's own disk code is loaded yet.

DOS &404A : no failures against this sector yet
DOS &404E : remember where it is to land

DOS &4053 step
    Bit 7 of the track number is the side.  The controller has no notion
    of sides -- it is told which head to energise by which port block is
    used -- so the bit comes out of the track number and selects the
    other base instead.


DOS &405B step
    Two ports up is the sector register.  Set the sector, then step back
    down to the command and status register, which is where the rest of
    the loop works.

DOS &4061 step
    Wait for the controller to go idle, then read back the track it is
    actually over.

DOS &4063 : bit 0 of the status is BUSY

DOS &4069 step
    Compare the head's track with the one wanted, and step towards it
    one track at a time.  There is no seek command in use here: the
    controller is stepped by hand and the track register read back after
    each move.

DOS &406B : already there
DOS &406D : the head is beyond the track wanted
DOS &4071 : the head is short of it
DOS &4079 : round again to see where the head has got to

DOS &407B step
    On the right track.  Ask for the sector and let the command settle
    before the first status read.

DOS &4083 : where this sector is to land

DOS &4086 step
    Put the data register's port in B.  The three entries differ only in
    how much of the sum is already done: MasterBASIC jumps into whichever
    suits what it has in hand, and all three arrive at the command port
    plus three.

DOS &408C step
    The transfer.  One byte at a time from the data register, with the
    port switched between data and status on every pass, because the two
    tests and the read use different registers of the same chip.

DOS &4091 : back to the command and status register

DOS &4096 expr DISK_STATUS_DRQ_BIT
DOS &4096 : a byte is waiting to be taken
DOS &409A : bit 0 is BUSY: still running, so go round again

DOS &409D step
    The command has finished; was the sector any good?

    THIS MASK IS WRONG.  A holds the status rotated one place right, from
    the RRCA above, so a mask applied here is in rotated space, and &0D
    in rotated space is DRQ, CRC ERROR and RECORD NOT FOUND.  DRQ cannot
    be set -- the loop only leaves when it is clear -- so what the
    instruction tests is CRC ERROR and RECORD NOT FOUND, and nothing
    else.

    It should be &0E: LOST DATA, CRC ERROR and RECORD NOT FOUND.  That is
    not a guess about what was meant.  &0E is the mask the DOS uses for
    exactly this question at &46C6, on a status rotated in exactly the
    same way, and it is the DOS source's own AND &1C shifted one place to
    suit the rotate.  &0D is that same error set written for a status
    that has not been rotated -- BUSY, LOST DATA and CRC ERROR.  The
    shift was made at &46C6 and forgotten here.

    THE ROTATE SWAPS THE TWO ENDS OF THE MASK, which is what makes this
    hard to see by eye.  Read as an ordinary mask &0D is BUSY, LOST DATA
    and CRC ERROR: it appears to test LOST DATA and to miss RECORD NOT
    FOUND.  After the rotate it is the other way about -- RECORD NOT
    FOUND is tested and LOST DATA is not.

    THE CONSEQUENCE is that a sector which arrives with a byte dropped is
    accepted as good.  LOST DATA is exactly the failure a polled transfer
    suffers when something holds the processor up too long, and it is the
    one error of the three that this test cannot see.

    WHERE IT CAME FROM.  SAMDOS, which this DOS grew out of, gets the
    same test right, and does it by never rotating at all: its transfer
    loops are unrolled, its BUSY test is BIT rather than a rotate, so A
    is always the status as read and its mask is the plain %00011100.
    Its own name for that constant settles what the three bits are meant
    to be -- "mask of lost data, CRC error and record not found".

    MasterDOS rolled those loops up and swapped the BIT for an RRCA,
    which is a byte shorter and a little faster in the tightest loop in
    the DOS.  That is the change that made a shifted mask necessary.
    %00011100 shifted is &0E, and &0E is what &46C6 got; the three loops
    got &0D.

    These seven instructions appear three times -- here, at &48DB and at
    &4A28 -- so the boot loader, the block load and the block save all
    have it.  The ordinary sector read and write do not: they reach
    &46C6 and get the right mask.

DOS &409F : a clean read

DOS &40A1 step
    The read failed.  Count it, and on every other pair of failures
    restore the head to track 0 first, on the theory that a mis-seek is
    the likeliest cause.

DOS &40A9 : bit 1 of the count

DOS &40B5 step
    Ten attempts at one sector, then give up.  There is no error
    reporting here yet either: the system page has to be put back at
    &0000 before the ROM can be asked to print anything.

DOS &40B8 : try the sector again
DOS &40BA : the ROM needs to be low again to report anything

DOS &40C0 step
    The sector is in.  Its last four bytes are the track and sector of
    the next one; zero for both ends the file.

DOS &40C7 : the end of the chain
DOS &40C9 : more of this wave to read

DOS &40CB step
    The end of the first wave, which is the DOS.  Enough of it is now in
    memory to install the part that lives in the system page, and the
    second wave -- MasterBASIC -- follows into the next page down.

DOS &40DD BOOT_NEXT_SECTOR_TRAMPOLINE
    Back round for the next sector.  It is an absolute jump through the
    window, not the JR the loop would otherwise use: the DJNZ that
    reaches it is already at the limit of its range, and this is far
    enough away to need three bytes anyway.

DOS &40E0 BOOT_LOAD_COMPLETE
    Both waves are in.  B counts the sectors of a wave and the DJNZ at
    &40C9 goes back for the next one; getting here instead means the
    chain ended -- the last sector's final four bytes were zero -- so
    there is nothing left to read.

DOS &40D2 step
    The end of a wave.  The page number found earlier comes back off the
    stack, and LMPR is set to one below it -- which puts that page itself
    at &4000-&7FFF, since LMPR names the page at &0000 and the next one
    follows it.  So from here to the end of BOOT, &4000 is the page the
    second wave is being read into: MasterBASIC's.

    That is why the next instruction can load HL with &4000 and mean the
    start of a page that is not this one, and why &75E1 below is
    MasterBASIC's INSTALLER rather than anything in this half.

    These two instructions are shared.  PTHRD is a routine in its own
    right, called from three places in the RAM disc code, and the boot
    falls into it rather than calling it; the carried comment about a
    path name belongs to that other use and not to this one.

DOS &40D4 : the page the DOS was loaded into, less one
DOS &40D6 : LMPR bit 6, so the ROM stays available at &C000
DOS &40DA expr &4000
DOS &40DA : the base of that page, where the second wave starts

DOS &40E0 step
    Both waves are in.  Copy INSTALLER -- 943 bytes at MasterBASIC's
    &75E1, which is at &4000 just here -- into the DOS's buffer area
    through the window, and jump to it there.  From &40F6 on, the code
    that runs is the copy at DOSBUF and not anything in these listings.

DOS &40E0 expr &75E1
DOS &40E0 : INSTALLER, in the page LMPR has just put at &4000

DOS &40E3 : the installer's landing ground, reached through the window
DOS &40EB : the page the DOS is in
DOS &40EF : one below it, which is MasterBASIC's
DOS &40F0 : written into MasterBASIC's &42CC, not this half's: its page
DOS &40F6 : and away, into the copy
