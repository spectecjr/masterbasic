# Reading a file specification: the name, and the device and drive
# prefix in front of it.
#
# Prose for listings/clean/ only.

GROUP Characters
CONST CH_COLON = &3A : the statement separator in BASIC, and what ends a device or drive prefix in a file name
CONST CH_SPACE = &20 : space
CONST NAME_LENGTH = &0A : characters in a file name
CONST NAME_FIELD = &0E : the fourteen characters NSTR1 keeps: the name, and room for the prefix
CONST LONG_NAME_LIMIT = &4F : the longest name the system-page buffer takes, which is a path

DOC EVNAM
    Evaluate a file name, and keep it twice.

    THE STRING CAN BE UP TO 79 CHARACTERS, because it may be a path,
    and the whole of it goes to the ROM's buffer at &4F10 with its
    length at &4F60, which is where part SUBD reads a path from.  The
    first fourteen go to NSTR1+1 as well, padded out with spaces, and
    that copy is what everything that only wants a name reads --
    fourteen rather than ten because a "D1:" prefix has not been
    stripped yet, and EVFILE strips it from there.

    An empty name and a name over 79 are both "Invalid file name".

DOS &61D8 expr LONG_NAME_LIMIT
DOS &61DB : longer than that is an error
DOS &61E3 expr NAME_FIELD
DOS &61E6 : shorter than the field: copy what there is
DOS &61EA expr NAME_FIELD
DOS &61EA : longer: the field's worth, and the rest goes only to the long buffer
DOS &61F0 : fifteen bytes: the type byte and the field
DOS &61F2 expr CH_SPACE
DOS &61FF expr PAGE_VALUE_MASK
DOS &61FF : the page the string is in, out of SVC
DOS &620E : the ROM's buffer, where the whole name goes
DOS &6214 : the ROM's LDIR, called there so that the copy lands in the system page

DOC EVFILE
    Take the device and drive off the front of the name in NSTR1+1.

    WHAT IT ACCEPTS is a letter, then up to two digits, then a colon:

        T:name        device T, no number
        D1:name       device D, drive 1
        D12:name      two digits, taken as a number
        D1            no name, which becomes "D1:*"
        D1 (spaces)   the same, with the field blank after the digit
        name          no prefix at all

    A LETTER ON ITS OWN NEEDS THE COLON.  With no colon after the letter
    the second character has to be a digit, and with no digit there is
    no prefix: the whole field is the name and HL goes back to its
    start.  Only "D" is allowed to drop the colon, and only when nothing
    follows the digit but spaces -- C11SP checks the eleven characters
    after it -- so that DIR "D1" means the whole of drive 1.  And only
    "D" may take a single digit at all: for any other letter one digit
    has to be followed by a second and then the colon, so "T1:name" is
    a bare name and "T12:name" a prefix.

    A NULL NAME IS &FF from the ROM, and becomes "T:": the tape, with
    no name, which is what LOAD "" has always meant.

    WHAT COMES OUT.  The letter goes to LSTR1 and the number, through
    CODN's pretend table, to DSTR1; TEMPW3 holds how many characters
    the prefix took, and the name is copied to the front of the field
    from wherever it started, so NSTR1+1 reads as a bare name from here
    on.

DOS &6709 : &FF is the ROM's empty name
DOS &670D : "T", for the tape
DOS &6711 expr CH_COLON
DOS &6714 expr CASE_BLIND
DOS &6714 : the letter, either case
DOS &6719 expr CH_COLON
DOS &671B : letter and colon: a device with no number
DOS &671D : "0", so a digit becomes its value
DOS &671F : ten and over was not a digit, so there is no prefix
DOS &6725 : "D" is the only letter that may drop the colon
DOS &672B expr CH_COLON
DOS &672F : nothing after "D1:" but spaces?
DOS &6736 expr CH_SPACE
DOS &6738 : not "D1 " either, so a second digit is expected
DOS &673A : nothing after "D1 " but spaces?
DOS &673F expr CH_COLON
DOS &6742 expr CH_STAR
DOS &6747 : "0", so a digit becomes its value
DOS &6749 : ten and over was not a digit
DOS &6757 expr CH_COLON
DOS &6759 : two digits and no colon is no prefix
DOS &675C : the number, through the pretend table, to DSTR1
DOS &6771 expr NAME_LENGTH
DOS &6779 : and four spaces after it, to fill the field

DOC ALPHA
    Carry if A is a letter, either case.  Two range tests, each a
    compare against the first letter and one against the character
    after the last, with CCF inverting the first compare's carry so
    that RET NC leaves on "below the range".  ALPHANUM adds the
    digits, through NUMERIC.

DOS &62D8 : "A"
DOS &62DB : below it: not a letter
DOS &62DC : one past "Z"
DOS &62DE : so carry means A to Z
DOS &62DF : "a"
DOS &62E2 : between the two ranges: not a letter
DOS &62E3 : one past "z"
DOS &504C : one past "9"
DOS &504F : "0", and CCF makes carry mean a digit

DOS &734E : one character of it
DOS &7353 : "T": the tape gets a space, anything else the "*" after it

DOS &5EE4 : a comma
DOS &5EE8 : or a semicolon
DOS &73D6 : the count in C alone
DOS &73DB : ten less the name's length is how many spaces pad it

DOC EXDT1
    Swap BC bytes between HL and DE: &0306 from BSWOP, where BUDT set
    it, &58 from EXDATX and &1C from EXDAT.

# The carry-across kept only the first line of BUDT's exit comment.
DOS &6272 : GET HL=RPT, DE=PAGED IN BUFFER, BC=0306H

DOC C11SP
    Are the eleven characters after HL all spaces?  Z if so, and HL is
    left where it was.  Eleven is what is left of the fourteen-
    character field after the two characters the callers in EVFILE
    have already passed and the one HL sits on; a two-digit prefix,
    "D12:", never comes here.

DOS &678C : eleven characters
DOS &6791 expr CH_SPACE

DOC CODN
    Map a drive number through DRPT, the table that lets each drive
    pretend to be another.  Numbers outside 1 to 7 are left alone.

DOS &61A0 : 1 to 7, tested as 0 to 6 after the DEC
DOS &61A8 : the high byte of the index

DOS &634D : "T", the tape
DOS &6351 : "N", the network; anything else is "Invalid device"
DOS &63D7 : offset 36 of the header: the high byte of the length within its last page
DOS &63E9 : eighty is the displacement from the ROM's HDR to its HDL, added to IX at TXRM; the count is the forty-eight loaded at &6409

DOC EVFL75
    A tape or network header: set the ROM's temporary device and speed,
    and hand the name across.

    THE NUMBER AFTER "T" IS A TAPE SPEED, and one below 8 -- a drive
    number, in effect -- is replaced by the ROM's default of 112 before
    it is written to the byte after SLDEV.  A blank name becomes the
    ROM's &FF; anything else is copied whole, all fourteen characters.

DOS &635E : below 8 is a drive number, not a speed
DOS &6362 : TSPEED, the ROM's default
DOS &6364 : the byte after SLDEV, the temporary device number -- a speed, for tape
DOS &636D expr CH_SPACE
DOS &636F : a name, so copy it
DOS &6371 : &FF is the ROM's empty name
DOS &637B expr NAME_FIELD

# PART F12's entries that had no banner of this project's own.

DOC SEPARX
    A separator, or nothing: SEPAR tests for one and returns Z if it
    found it; anything else falls into REP0, "Nonsense in BASIC".

DOC REP0
    The ROM's error 29, "Nonsense in BASIC", through DERR: where a
    parse gives up on a character it cannot place.

DOC AHLNX
    A:HL as a 20-bit flat address: the two top bits of H become the low
    two of the page, A's four low bits stand above them, and HL keeps
    the fourteen bits of offset.  AHLN masks the page to three bits
    for a nineteen-bit answer.

DOC IOOR
    The ROM's error 30, "Integer out of range", through DERR.  Nine
    callers, none of them a fall-through from AHLNX above.

DOC WIOOR
    IOOR by a jump, for the branches inside the FORMAT checks that are
    too far for a JR.

DOC WIORH
    The last of FORMAT's range checks, falling into the format proper:
    NC from the compare above means the track total, less two, has
    reached the limit in B -- 158 less the directory's extra tracks --
    and that is "Integer out of range".

DOC EVNAMX
    EVNAM after a NEXTCHAR: the file name that follows a separator.

DOC EVNM2
    EVNAM past the string fetch, with BC its length and the page in
    SVC: empty or over LONG_NAME_LIMIT is "Invalid file name", and
    otherwise the name goes to the ROM's buffer at &4F10 whole and to
    NSTR1+1 fourteen characters at most, space padded.

DOC EVNAM2X
    The second file name of a two-name command, after a NEXTCHAR: the
    parameter blocks are swapped with EXDATX and the name read with
    EVNAM, so that it lands in the block that is now first.

DOC EXDATX
    EXDAT, and the string buffer with it: the eighty-eight bytes at
    &4F10 in the system page swapped with the copy at &4F68, so that a
    two-name command keeps both names' long forms.

DOC BSWOP
    EXDAT for the sector buffer as well: the parameter blocks swapped,
    DTKS exchanged with DTKSX so each file keeps its own directory
    depth, and the &0306 bytes from RPT exchanged with the paged-in
    buffer BUDT points at, through EXDT1.

DOC EVST2
    Fetch a string that has been evaluated, when running: GETSTR, with
    the page it lives in kept in SVC and put in H.  Z at syntax time,
    with nothing done.

DOC EVSRM
    A stream number after a NEXTCHAR: EVSRMX.

DOC EVSRMX
    Evaluate a stream number and record it in SSTR1: seventeen and up
    is "Invalid stream number" through EVSRE, and 16 itself is the
    ROM's -4.  Z at syntax time, with nothing recorded.

DOC EVNUMX
    A number after a NEXTCHAR: EVNUM.

DOC EVNUM
    Evaluate a numeric expression through the ROM's EXPNUM and, when
    running, fetch it as an integer into BC; Z at syntax time, with A
    kept across the fetch.

DOC EVNU2
    EVNUM's tail: nothing more at syntax time, else the integer through
    CGTINT.

DOC CGTINT
    The ROM's GETINT through CMR, with A kept: the number on the
    calculator stack into BC.

DOC TRX0
    TRX with HL already on the source entry: fifteen bytes into NSTR1
    -- type, name and the four after it -- and then the name copied
    over character by character from NSTR3, where the target pattern
    waits: a "?" there keeps the character the disc had, and a "*"
    keeps the rest.
