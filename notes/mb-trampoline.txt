# Getting back into MasterBASIC from somewhere it is not paged in.

MB &5CDF : &E7 is RST &20, which PAGE_IN_ROM1 plants at &4D50 before anything else goes in

MB &5CE1 expr SYS_CDBUFF_50+&4000
MB &5CE1 : CDBUFF+&50 seen through the window.  PAGE_IN_ROM1 exchanges it with the ROM address in DE, so this is where the copy lands and not where it comes from

MB &5CE8 : the nine bytes of the intercepted routine's head -- for POKE, its three opening CALLs, stopping one byte short of the JR NZ the JP NZ below replaces

MB &5CEE : &C2 is JP NZ, and the two bytes after it are filled in at run time

MB &5CF8 : &D0 is RET NC

MB &5CFB : &3E is LD A, whose operand the three instructions below work out -- LMPR plus one, this half's own page

MB &5D05 : &D3 is OUT (n),A

MB &5D08 value HMPR
MB &5D08 : the port that OUT is given, so the pair reads OUT (HMPR),A

MB &5D0B : &21 is LD HL, and DE goes in as its operand

MB &5D12 : &C3 is JP

MB &5D15 : its operand -- this half's own &5D20, seen from a page where this half is at &8000

MB &5D1B expr SYS_CDBUFF_50
MB &5D1B : the address of what has just been built, which RESTORE_HMPR_AND_STORE writes through V4076 so that whoever needs the trampoline can find it

MB &5D2B : &45 is the sixty-nine bytes of the far-move helper

MB &5D2F expr SYS_CDBUFF_50+3
MB &5D2F : three bytes past the RST &20 and the nine copied, which is where the ROM's own CALL &1D01 now sits

MB &5CDF BUILD_PAGE_IN_TRAMPOLINE

DOC BUILD_PAGE_IN_TRAMPOLINE
    Assemble a short routine in the ROM's code buffer whose whole job is
    to page MasterBASIC in and jump into it.

    It plants an RST &20 at &4D50 in the system page -- CDBUFF+&50,
    where hook 185 also builds -- copies nine bytes after it from the
    ROM routine the command table named, and then writes the rest a byte
    at a time, opcode by opcode, from &4D5A:

        C2 00 00      JP NZ,&0000     the operand is filled in later
        D0            RET NC
        3E nn         LD A,page       LMPR+1, this half's own page
        D3 FB         OUT (HMPR),A
        21 nn nn      LD HL,src+9     the ROM source past the nine bytes
        C3 20 9D      JP &9D20

    THE NINE BYTES ARE THE HEAD OF THE ROM ROUTINE BEING INTERCEPTED.
    HCMDV reads the command-table entry into DE at &4EB2 and this runs
    for token &E1, POKE, which ROM 3.0's table at &FD65 gives as &1205.
    The nine bytes there are CD E4 3A CD 85 3A CD 08 3B -- POKE's three
    opening CALLs, stopping one byte before its own JR NZ,POKE2, which
    the JP NZ above replaces with the absolute form.  The LD HL operand
    is the source plus nine for the same reason: the block at &5D20
    copies &15 more bytes on from there, so the JP &4D53 lands exactly
    on the ROM's CALL &1D01.

    &9D20 is in the window, so it is this half's &5D20 seen from a page
    where this half sits at &8000.  The trampoline therefore pages
    MasterBASIC into the window and jumps straight into it, carrying HL.

    Finally LD BC,&4D50 and a fall into RESTORE_HMPR_AND_STORE, which
    puts HMPR back and writes &4D50 -- the address of what was just
    built -- through the pointer in V4076, so whoever needs the
    trampoline can find it.

    That is the third builder into CDBUFF, after &735D at +&11 and hook
    185 at +&50.  This one lands at +&50 as well, so it and the hook are
    alternative users of the same space rather than both being live.

MB &5D20 : where the trampoline lands, with this half paged in at &8000
