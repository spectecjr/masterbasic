# The thirty-six bytes installed at &4BA0: six stubs, each turning a ROM
# vector call into one of MasterBASIC's hook codes.

MB &7B90 PRTOKV_STUB
MB &7B9A EVALUV_STUB

DOC PRTOKV_STUB
    What PRTOKV points at, installed at &4BB0.

    A token below &F7 is the ROM's own and gets RET C, so the ROM prints
    it.  Anything above is MasterBASIC's: the return address is dropped,
    XPTR is picked up, and hook &A9 raised, which reaches HPRTOK.

DOC EVALUV_STUB
    What EVALUV points at, installed at &4BBA.

    &25 passes, and so does anything below &21; the rest returns with
    carry clear for the ROM to deal with.  What is left drops the return
    address and raises HK_HKLEN.

# The block, at &7B80 in this listing and &4BA0 when it runs:
#
#     +&00  &40, then JR over the next stub
#     +&03  hook &97
#     +&06  HK_MCHWR
#     +&09  HK_MCHRD, with EXX : PUSH BC : POP AF to fetch the flags back
#     +&10  PRTOKV_STUB
#     +&1A  EVALUV_STUB
#
# Each is three to ten bytes and does nothing but raise a hook, which is
# the whole trick: the ROM's vectors take an address, MasterBASIC's own
# dispatcher takes a code, and these are the join between the two.
#
# Both halves of that shape are the documented contract, not something
# these stubs invented.  The Technical Manual, on SETIYV but saying "as
# with all the vectors":
#
#     your routine making just RET will cause the normal ROM routine to
#     be executed.  Thus your code might start with a check ... and RET
#     if so.  Otherwise, POP the return address so that the ROM routine
#     is never used
#
# which is exactly PRTOKV_STUB: CP &F7 : RET C to let the ROM have it,
# POP HL and a hook otherwise.  The manual's own worked example for
# LPRTV even writes the second half as "POP BC ;JUNK RETURN ADDRESS".
#
# And it says why the stubs are small and live where they do:
#
#     USRPTCH must be in the system page to guarantee it is resident
#     when the vector is called ... it is a good idea to use a short
#     routine in the Heap to call a large routine in another page
#
# That is the whole architecture in two sentences: small resident stubs
# in the system page, the real code paged in behind them.
#
# What each vector is called with, from the same section:
#
#   PRTOKV  A = token code to expand and print as ASCII
#   EVALUV  A = current character in expression; for adding functions
#   CMDV    A = the code about to be syntax checked or executed,
#           "normally a command code" -- which is what
#           DISPATCH_ON_COMMAND_TOKEN switches on, arriving in H
#   RST8V   A = error code, alternate registers selected, CHAD and
#           CHADP already copied to XPTR and XPTRP, DE pointing at the
#           code byte after the RST 08H
#   MTOKV   called when a spelled-out keyword is not recognised, DE
#           pointing at it; exit as jump table entry JGTTOK
#   EDITV   called before the editor is used for a line or INPUT
#   FRAMIV  called by the frame interrupt, 50 times a second
#
# RST8V's entry conditions are worth keeping: XPTR being set up before
# the vector is reached is why PRTOKV_STUB can read it straight.
#
# The same bytes are DUMP's greyscale tables once the block is installed
# and this copy is dead -- see notes/mb-dumpcolour.txt.

# PUTSWA, and where it points.
#
# The manual: "POKE DPEEK XVAR 0,0 will make PUT use the ROM's version of
# PUT.  POKE DPEEK XVAR 0,172 (the code for PUT) to use MasterBASIC's
# faster version again."
#
# 172 is &AC, the PUT token, and the byte it names is the operand of the
# CP &AC at &7C55 in this listing -- &48FF once the block is installed,
# inside DISPATCH_ON_COMMAND_TOKEN.  Zero it and the comparison can never
# match, so PUT falls through to the ROM; put &AC back and it jumps to
# &45A2, the extended PUT INSTALL_EXTENDED_PUT built.
#
# So the manual describes the switch from the outside and the dispatcher
# is what it switches.  Two things that had been left open in
# notes/mb-relocated.txt -- what H holds, and why &7C57 jumps to &45A2 --
# are the same question, and this is the third witness to the answer
# after the token table and the dump.
