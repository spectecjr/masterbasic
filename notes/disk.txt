# SELD works out which drive's port block to use.  &E0 is the disk
# command register nearly everywhere else in the DOS, so these two are
# named here and nowhere else.

DOS &4835 value DISKCTL_0_BASE
DOS &4839 value DISKCTL_1_BASE

# DSC holds the selected drive's base port, which on the WD1772 is the
# command register on write and status on read.  Adding 3 reaches the
# data register.  Every one of these is a LD A,(DSC) followed by a patch
# into an IN, then this, then a patch into another IN.
#
# Rename it in one line if you would rather it were called something
# else: RENAME DISKCTL_DATA_OFS <name>

DOS &4599 value DISKCTL_DATA_OFS
DOS &45CE value DISKCTL_DATA_OFS
DOS &4657 value DISKCTL_DATA_OFS
DOS &4691 value DISKCTL_DATA_OFS
DOS &48C4 value DISKCTL_DATA_OFS
DOS &4A01 value DISKCTL_DATA_OFS



DOS &446C UNWIND_HOOK_STACK
    Take the return address into IY, read DOSSTK, and LDDR six bytes down
    from &7FFF -- the stack the DOS unwinds to when a hook gives up.

DOS &4495 CLEAR_TSTR
    Fill TSTR1 up to UIFA with &FF and set RDAT to the same, which is the
    DOS's "nothing here" for a temporary string and its data flag.  The
    length is written as UIFA-TSTR1 so the two can move without this
    needing to know how far apart they are.

DOS &4580 WRITE_SECTOR
    A sector out: wait for the drive with DWAIT, check the track through
    TIRDXDCT, then interrupts off, CTAS and PRECMX to position, and the
    drive's status port poked into CHECK_WRITE_STATUS's own operand from
    DSC before the transfer.

DOS &45B7 READ_SECTOR
    The read side, and the most called routine in this half.  TIRDXDCT
    checks the track, RSSR selects the sector, RDDATA does the transfer,
    and a failure goes round again from &45BD rather than giving up at
    once.

DOS &45E2 SECTOR_FOR_CHANNEL
    Take the flags at (IX+&04) and decide how to reach the data: bit 2
    sends it through GETSCR for a screen, and what comes back is checked
    against &04 before being used.

DOS &4628 SET_SCREEN_POINTER
    Store HL in PTRSCR and put PORT1 back into HMPR, which is the pair
    that ends every access to a screen the DOS has borrowed.

DOS &467F READ_SECTOR_TO_ADDRESS
    Like READ_SECTOR but with the destination given: the drive's data
    port is poked into the operands of SRSA3 and SRSA2 -- the two
    instructions the transfer loop uses -- and the address pushed for
    them before it starts.

DOS &46C6 RETRY_OR_GIVE_UP
    What the sector routines do with a controller status they do not
    like.  AND &0E keeps the error bits, and any of them leaves for CDE1;
    otherwise the buffer is re-got through GTBUF and the operation runs
    again.  The path at &46D1 counts the failure into DCT, the disc error
    counter.

DOS &477B STEP_HEAD_OUT
DOS &477F STEP_HEAD_IN
    One step of the head, either way: the direction is the only
    difference and both fall into the same code, which issues the command
    and then consults V42BB -- the double-step setting the manual calls
    DBSTP, "can be POKEd to a non-zero value to cause double stepping of
    the drive head ... useful when reading 40-track disks" -- and repeats
    the step when it is set.

DOS &4829 SELECT_DRIVE
    Take the drive from (IX+&0B), record it in DRIVE, and pick the port
    block: DISKCTL_0_BASE for one drive and DISKCTL_1_BASE for the other,
    chosen on the number rather than by two copies of the code.

DOS &4847 IS_LAST_PAGE
    GRPNT, then return NZ unless the page count says &FE with one page
    left -- the shape the DOS uses for "this is the last page of the
    transfer".

DOS &4856 ROOM_LEFT_IN_PAGE
    How much of the current page is still to come: &01FE less the offset,
    with the page adjusted first, and the result narrowed against what
    the caller has left.

DOS &4E75 CHECK_FILE_TYPE
    The file type out of the header, masked to five bits and bounded: &15
    or more is "wrong file type", and &12 to &14 -- the three SAM types --
    are separated by SUB &12 with ADC A,&00, so one subtract and one add
    do the work of two comparisons.

DOS &4EE3 COPY_HEADER_FIELDS
    Nine bytes from HD002 into the buffer GRPNTB points at, and then on
    to V42E2.  The &D3 in B is which buffer GRPNTB is to fetch.

DOS &4F67 FILL_DE_WITH_A
    B bytes of A at DE.  Three instructions, four callers, and &4F69 is
    the entry for a caller that has already written the first one.

DOS &4F6C FILE_TYPE_AT_POINT
    POINT, then the type byte masked to five bits and compared with &07 --
    the DOS's own directory-entry type -- with &04 standing in for it
    when it matches.

DOS &4F84 RESET_BUFFER_POINTERS
    Point IX at DOSBUF and BUF at DRAM, then fall into the pair below
    that clears the two counts at (IX+&0D) and (IX+&0E).  Everything that
    starts a fresh transfer comes through here.

DOS &4F8E CLEAR_TRANSFER_COUNT
    Just those two bytes, for a caller whose buffer is already set up.

DOS &4FBF GET_TRACK_AND_SECTOR
DOS &4FC6 SET_TRACK_AND_SECTOR
    The track and sector at (IX+&11) and (IX+&12), read into DE and
    written from it.  &4FCD is the third of the family: it reads the old
    pair out through GET_TRACK_AND_SECTOR and puts HL in its place, so a
    caller can exchange them in one call.

DOS &4FCD SWAP_TRACK_AND_SECTOR
    Read the old track and sector out into DE and put HL in their place,
    which is the exchange the three-routine family above exists for.

DOS &4FD7 REPORT_PAGE_COUNT
    Hand (IX+&0E) to MasterBASIC's BYTE_TO_DECIMAL through CALLMB, so the
    page count can be printed as three characters.

DOS &4FE0 CLAIM_FREE_SLOT
    Take FSLOT if nothing has it -- a non-zero value returns at once --
    and record the entry beside it in FSLTE.

DOS &4FF3 IS_END_OF_STATEMENT
    Carriage return or colon, returning Z for either, which is the DOS's
    own copy of the test MasterBASIC spells AT_END_OF_STATEMENT.

DOS &51A7 PRINT_BYTE_AS_DECIMAL
    Three characters from a byte, through MasterBASIC's BYTE_TO_DECIMAL.
    The DOS has no such routine of its own, so it calls across for it.

DOS &56BB PRINT_DATE_IF_SET
    Fetch the &F5 buffer through GRPNTB, and return unless the first byte
    is set -- INC A then CP &02 rejects both &FF and &00 in one test.
    Otherwise "/" goes in C as the separator and the fields are printed
    in pairs.

DOS &56D0 PRINT_TWO_FIELDS
    Two fields and a separator between them: print, separator, print,
    separator, using the byte in C each time.

DOS &56DE PRINT_FIELD
    One field as a decimal number through the ROM's PNUM2, with HL, DE
    and BC all saved around it, so the caller's pointer survives.
