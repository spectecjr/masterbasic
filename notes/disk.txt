# SELD works out which drive's port block to use.  &E0 is the disk
# command register nearly everywhere else in the DOS, so these two are
# named here and nowhere else.

DOS &4835 value DISKCTL_0_BASE
DOS &4839 value DISKCTL_1_BASE

# DSC holds the selected drive's base port, which on the WD1772 is the
# command register on write and status on read.  Adding 3 reaches the
# data register.  Every one of these is a LD A,(DSC) followed by a patch
# into an IN, then this, then a patch into another IN.
#
# Rename it in one line if you would rather it were called something
# else: RENAME DISKCTL_DATA_OFS <name>

DOS &4599 value DISKCTL_DATA_OFS
DOS &45CE value DISKCTL_DATA_OFS
DOS &4657 value DISKCTL_DATA_OFS
DOS &4691 value DISKCTL_DATA_OFS
DOS &48C4 value DISKCTL_DATA_OFS
DOS &4A01 value DISKCTL_DATA_OFS



DOS &446C UNWIND_HOOK_STACK
    Take the return address into IY, read DOSSTK, and LDDR six bytes down
    from &7FFF -- the stack the DOS unwinds to when a hook gives up.

DOS &4495 CLEAR_TSTR
    Fill TSTR1 up to UIFA with &FF and set RDAT to the same, which is the
    DOS's "nothing here" for a temporary string and its data flag.  The
    length is written as UIFA-TSTR1 so the two can move without this
    needing to know how far apart they are.

DOS &4580 WRITE_SECTOR
    A sector out: wait for the drive with DWAIT, check the track through
    TIRDXDCT, then interrupts off, CTAS and PRECMX to position, and the
    drive's status port poked into CHECK_WRITE_STATUS's own operand from
    DSC before the transfer.

DOS &45B7 READ_SECTOR
    The read side, and the most called routine in this half.  TIRDXDCT
    checks the track, RSSR selects the sector, RDDATA does the transfer,
    and a failure goes round again from &45BD rather than giving up at
    once.

DOS &45E2 SECTOR_FOR_CHANNEL
    Take the flags at (IX+&04) and decide how to reach the data: bit 2
    sends it through GETSCR for a screen, and what comes back is checked
    against &04 before being used.

DOS &4628 SET_SCREEN_POINTER
    Store HL in PTRSCR and put PORT1 back into HMPR, which is the pair
    that ends every access to a screen the DOS has borrowed.

DOS &467F READ_SECTOR_TO_ADDRESS
    Like READ_SECTOR but with the destination given: the drive's data
    port is poked into the operands of SRSA3 and SRSA2 -- the two
    instructions the transfer loop uses -- and the address pushed for
    them before it starts.

DOS &46C6 RETRY_OR_GIVE_UP
    What the sector routines do with a controller status they do not
    like.  AND &0E keeps the error bits, and any of them leaves for CDE1;
    otherwise the buffer is re-got through GTBUF and the operation runs
    again.  The path at &46D1 counts the failure into DCT, the disc error
    counter.

DOS &477B STEP_HEAD_OUT
DOS &477F STEP_HEAD_IN
    One step of the head, either way: the direction is the only
    difference and both fall into the same code, which issues the command
    and then consults V42BB -- the double-step setting the manual calls
    DBSTP, "can be POKEd to a non-zero value to cause double stepping of
    the drive head ... useful when reading 40-track disks" -- and repeats
    the step when it is set.

DOS &4829 SELECT_DRIVE
    Take the drive from (IX+&0B), record it in DRIVE, and pick the port
    block: DISKCTL_0_BASE for one drive and DISKCTL_1_BASE for the other,
    chosen on the number rather than by two copies of the code.

DOS &4847 IS_LAST_PAGE
    GRPNT, then return NZ unless the page count says &FE with one page
    left -- the shape the DOS uses for "this is the last page of the
    transfer".

DOS &4856 ROOM_LEFT_IN_PAGE
    How much of the current page is still to come: &01FE less the offset,
    with the page adjusted first, and the result narrowed against what
    the caller has left.

DOS &4E75 CHECK_FILE_TYPE
    The file type out of the header, masked to five bits and bounded: &15
    or more is "wrong file type", and &12 to &14 -- the three SAM types --
    are separated by SUB &12 with ADC A,&00, so one subtract and one add
    do the work of two comparisons.

DOS &4EE3 COPY_HEADER_FIELDS
    Nine bytes from HD002 into the buffer GRPNTB points at, and then on
    to V42E2.  The &D3 in B is which buffer GRPNTB is to fetch.

DOS &4F67 FILL_DE_WITH_A
    B bytes of A at DE.  Three instructions, four callers, and &4F69 is
    the entry for a caller that has already written the first one.

DOS &4F6C FILE_TYPE_AT_POINT
    POINT, then the type byte masked to five bits and compared with &07 --
    the DOS's own directory-entry type -- with &04 standing in for it
    when it matches.

DOS &4F84 RESET_BUFFER_POINTERS
    Point IX at DOSBUF and BUF at DRAM, then fall into the pair below
    that clears the two counts at (IX+&0D) and (IX+&0E).  Everything that
    starts a fresh transfer comes through here.

DOS &4F8E CLEAR_TRANSFER_COUNT
    Just those two bytes, for a caller whose buffer is already set up.

DOS &4FBF GET_TRACK_AND_SECTOR
DOS &4FC6 SET_TRACK_AND_SECTOR
    The track and sector at (IX+&11) and (IX+&12), read into DE and
    written from it.  &4FCD is the third of the family: it reads the old
    pair out through GET_TRACK_AND_SECTOR and puts HL in its place, so a
    caller can exchange them in one call.

DOS &4FCD SWAP_TRACK_AND_SECTOR
    Read the old track and sector out into DE and put HL in their place,
    which is the exchange the three-routine family above exists for.

DOS &4FD7 REPORT_PAGE_COUNT
    Hand (IX+&0E) to MasterBASIC's BYTE_TO_DECIMAL through CALLMB, so the
    page count can be printed as three characters.

DOS &4FE0 CLAIM_FREE_SLOT
    Take FSLOT if nothing has it -- a non-zero value returns at once --
    and record the entry beside it in FSLTE.

DOS &4FF3 IS_END_OF_STATEMENT
    Carriage return or colon, returning Z for either, which is the DOS's
    own copy of the test MasterBASIC spells AT_END_OF_STATEMENT.

DOS &51A7 PRINT_BYTE_AS_DECIMAL
    Three characters from a byte, through MasterBASIC's BYTE_TO_DECIMAL.
    The DOS has no such routine of its own, so it calls across for it.

DOS &56BB PRINT_DATE_IF_SET
    Fetch the &F5 buffer through GRPNTB, and return unless the first byte
    is set -- INC A then CP &02 rejects both &FF and &00 in one test.
    Otherwise "/" goes in C as the separator and the fields are printed
    in pairs.

DOS &56D0 PRINT_TWO_FIELDS
    Two fields and a separator between them: print, separator, print,
    separator, using the byte in C each time.

DOS &56DE PRINT_FIELD
    One field as a decimal number through the ROM's PNUM2, with HL, DE
    and BC all saved around it, so the caller's pointer survives.

DOS &5766 PRINT_A_KEEPING_IT
    Print A through the ROM and give it back unchanged.  PUSH AF round a
    CMR to PRINT_A, and it is the most-called routine of its kind in this
    half: everything that prints a character and then wants to look at it
    again goes through here.

DOS &576E PRINT_WORD_AND_SPACE
    A bit-7-terminated word and then a space, the space through the ROM's
    SPC.

DOS &5774 SKIP_B_WORDS
    Step HL over B words, each ending at the character with bit 7 set.
    The RLA is the test and the two jumps are the two loops -- inner over
    a word, outer over the count -- with no counter of its own.

DOS &5815 PRINT_HEADINGS
    The directory's column headings, laid out as a row of CALL PTM with
    the text following each one inline.

DOS &597B EVAL_NAME_PAIR
    A filename, then optionally a second after a comma; without one, &8E
    stands in as the separator so the code below need not care which
    happened.

DOS &5C1B PRINT_B_CHARACTERS
    B characters from HL, each through PRINT_A_KEEPING_IT.

DOS &5C8B COLUMNS_FOR_DIRECTORY
    How many columns a directory listing gets: DCOLS if it is set, and
    otherwise MasterBASIC's SYS_CHAR_WIDTH read out of the system page --
    so a narrower character size gives a wider listing.

DOS &5D27 WRITE_BYTE_IF_OPEN
    Check the channel is open through OHASR, and if it is, store A and
    leave for WSAD to write the sector.

DOS &5E70 CALL_ROM_66CB
    HLFG with &66CB after it -- the inline-parameter convention again,
    with the ROM 1 address as the word.

DOS &6284 EVAL_STRING_IF_RUNNING
    A string expression, then CFSO so that syntax time returns without
    fetching it, and GETSTR only if the program is really running.  The
    page comes back in SVC.

DOS &6336 REQUIRE_SECTOR
    RXSS, and anything but Z is error 10.  Three callers use it as the
    "the sector had better be there" step before going on.

DOS &6482 HOOK_ARGS_TO_HEADER
    Unpack the registers a hook was called with -- HKHL, HKBC and HKDE --
    into the header fields HD0D1 and PGES1, clearing bit 7 of D on the
    way, which is the flag the caller used to mark a paged address.

DOS &6633 READ_SAVED_SECTOR
    Take the track and sector out of SVDE and read it, then leave for
    &5F4D rather than returning.

DOS &6701 DEFAULT_FILE_TYPE
    GTDEF, and if the type byte is &FF -- nothing chosen -- write &54 in
    its place before going on.

DOS &67FC CHANNEL_LENGTH_AND_FLAGS
    Take the two-byte length at (IX+&09) into BC and then look at the
    channel's flags: bit 1 through BITF1 sends it one way, and otherwise
    bit 5 of (IX+&04) is tested and the whole flag byte cleared.

DOS &68AB FIRST_DISC_CHANNEL
    Point IX at the channel table plus &1E -- CHANS read through the
    window and the offset added -- and return Z at once if the first byte
    is a carriage return, which is the DOS's empty-channel marker.

DOS &68DA STREAM_OR_CHANNEL
    Sort a stream number from a channel: bit 7 set means the other kind,
    and MSFLG decides which way round when it is.  B is zeroed first so
    the caller gets a pair either way.

DOS &6AEA CHANNEL_ENTRY_AT_ZERO_PAGE
    Zero HMPR so the system page is in the window, take CHANS from it and
    add &1E, then check the result with the ROM's CHKHL before reading
    through it.

DOS &6B77 RESET_CHANNEL_SCAN
    The same setup with IX instead of HL, and V4213 cleared first --
    which is what makes it the start of a scan rather than a single
    lookup.

DOS &6CD6 STORE_TRANSFER_COUNT
    Write the two count bytes at (IX+&0D) and (IX+&0E) out through the
    pointer &71F3 returns.

DOS &6D30 MOVE_TABLE_IF_PAGED
    Return at once unless the high byte of TEMPW1 says there is a page to
    deal with, and otherwise move the table below before going on.

DOS &6D4F COPY_MTBLS
    Eleven bytes from MTBLS, then &0308 bytes of zero after them -- the
    table and the room it needs, laid down in one go.

DOS &6F8D WRITE_LAST_PAGE
    The tail of a write: IS_LAST_PAGE decides whether this is the final
    page, and everything is pushed around the decision so the caller's
    registers survive either path.

DOS &6FC0 WRITE_AT_LINKED_SECTOR
    Take a track and sector out of the two bytes at HL, exchange them
    with the channel's through SWAP_TRACK_AND_SECTOR, and write there --
    which is how the DOS follows a file's chain of sectors.

DOS &6FCC COUNT_AND_READ_SECTOR
    ICNT, then fall into the entry below.  Three entry points, one after
    another, so a caller can start at whichever step it needs: count and
    read, read only, or neither.

DOS &6FCF SELECT_AND_READ_SECTOR
    SELECT_DRIVE then READ_SECTOR, and fall into the clear below.

DOS &6FD5 CLEAR_SECTOR_FLAG
    Bit 3 of (IX+&0C) down, then leave for SET_TRACK_AND_SECTOR.

DOS &7003 BUMP_TRANSFER_COUNT
    Add one to the two-byte count at (IX+&0D), carrying into (IX+&0E)
    only when the low byte wraps, so the common case is one INC and a
    RET NZ.

DOS &700B GET_STREAM_NUMBER
    A stream number through the ROM's GETINT, refused unless it fits in a
    byte and is below &10 -- INC H with DEC H tests the high byte without
    disturbing A.

DOS &7018 CHANNEL_FOR_STREAM
    STRMD gives the displacement, zero means no channel, and one less
    than it added to CHANS is where the stream's entry lives.

DOS &71F3 CHANNEL_LENGTH_FIELD
    IX plus LENL, in HL.  Five instructions for an offset that six places
    want, which is cheaper in bytes than writing the addition out at each
    of them.

DOS &730B PREPARE_DIRECTORY_WRITE
    SNDFL, error 32 if it fails, bit 2 of FLAG3 down, and then POINT and
    the type byte masked -- the run-up every directory write shares.

DOS &7533 RDRSCT
    Read a sector from a RAM disc -- the author's own name, from the part
    of the source ref/masterdos/docs/ram-discs.md calls RAMD.  Every disk
    operation starts with TIRD, and for drives 3 to 7 it comes here
    instead of touching a controller at all.

    The shipped code has one thing the reference source does not.  There
    RDRSCT is CALL GTBUF then LD BC,&0200 straight into RDRS2; here
    SDCHK2 goes between them, and its own comments say what it decides --
    "RET IF HL IN DRAM" and "CY IF HL WILL CROSS PAGE BOUNDARY".  A
    destination that would run off the end of a page takes the long way
    round through DRAM; one that will not is read into the caller's
    buffer directly.

DOC RDRS2
    The copy itself, and it is an LDIR: RDADR works out where the sector
    lives in the RAM disc's pages, and &0200 bytes move from there to
    DRAM.  A RAM disc read is a memory copy with the same interface as a
    floppy read, which is the whole point of the design.

DOS &778F READ_ADDRESS_CLEAR
DOS &7799 READ_ADDRESS_SET
    Read the sector's address mark through RDADR, and differ in one
    instruction: AND A leaves carry clear where SCF sets it, and both
    join at &77A1.  The flag is the caller's answer, carried out in the
    alternate accumulator.

DOS &7B35 TIME_TO_MINUTES
    Hours times twenty-four through MasterBASIC's MULTIPLY_BY_24, then
    the byte at HL added in with A extending the top -- the DOS reaching
    across for arithmetic it does not have of its own, as it does for
    BYTE_TO_DECIMAL.

DOS &7BA6 STACK_FIVE_BYTE_NUMBER
    Push a five-byte number onto the calculator stack through the ROM's
    STKSTR, with the paging handled by CMR.

DOS &7BAC RETURN_INTO_BC
    Write BC over the word at the stack pointer kept in &7FFC -- the
    ROM's stack as it stood when the DOS was entered -- so that the
    pending return goes to BC instead.  The same trick MasterBASIC plays
    with STORE_BC_AT_XVAR76, from the other side.
