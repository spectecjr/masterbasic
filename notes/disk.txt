DOS &446C SET_DOS_STACK
    Move the three words the ROM's PTDOS pushed at &7FFA-&7FFF down to
    just below DOSSTK, make that the stack, and keep the old ENTSP on
    it.  The 1991 source calls it SETSTK, "NEW STACK SO THAT DOS->CALL
    ROM->HOOKS CAN AVOID OVERWRITING MAIN DOS STACK": a nested entry
    through CMR starts at &8000 again and would land on the DOS's own
    stack if it were still up there.  Both entries, SYNTAX and HOOK,
    come through here; the return address goes into IY first so the
    LDDR can use the stack it is moving.

DOS &4495 CLEAR_TSTR
    Fill TSTR1 up to UIFA with &FF and set RDAT to the same, which is the
    DOS's "nothing here" for a temporary string and its data flag.  The
    length is written as UIFA-TSTR1 so the two can move without this
    needing to know how far apart they are.

DOS &4580 WRITE_SECTOR
    A sector out: wait for the drive with DWAIT, clear the retry count
    and test for a RAM disc through TIRDXDCT, then interrupts off, CTAS
    and PRECMX to position, and the
    drive's status port poked into CHECK_WRITE_STATUS's own operand from
    DSC before the transfer.

DOS &45B7 READ_SECTOR
    The read side, and the most called routine in this half.  TIRDXDCT
    checks the track, RSSR selects the sector, RDDATA does the transfer,
    and a failure goes round again from &45BD rather than giving up at
    once.

DOS &45E2 SECTOR_FOR_CHANNEL
    Take the flags at (IX+&04) and decide how to reach the data: bit 2
    sends it through GETSCR for a screen, and what comes back is checked
    against &04 before being used.

DOS &4628 SET_SCREEN_POINTER
    Store HL in PTRSCR and put PORT1 back into HMPR, which is the pair
    that ends every access to a screen the DOS has borrowed.

DOS &467F READ_SECTOR_COUNTING_DELIMS
    The source's "search version of RSAD": read a sector into the
    channel buffer -- RSSR falls into GTBUF, so HL is the buffer, as
    for READ_SECTOR -- comparing every byte with the delimiter in B on
    the way and counting DE down from (TEMPW1); the address after the
    DE-th delimiter goes to TEMPW2.  POINT's sector search is its one
    caller, "READ NEXT SECTOR, LOOKING FOR DELIM".  The drive's status
    port is poked into SRSA3 and its data port, three above it, into
    SRSA2, the two instructions the transfer loop uses; what is pushed
    at &4696 is DE, the track and sector.

DOS &46C6 RETRY_OR_GIVE_UP
    What the sector routines do with a controller status they do not
    like.  AND &0E keeps the error bits, and any of them leaves for CDE1;
    otherwise the buffer is re-got through GTBUF and the operation runs
    again.  The path at &46D1 counts the failure into DCT, the disc error
    counter.

DOS &477B STEP_HEAD_OUT
DOS &477F STEP_HEAD_IN
    One step of the head, either way: the direction is the only
    difference and both fall into the same code, which issues the command
    and then consults V42BB -- the double-step setting the manual calls
    DBSTP, "can be POKEd to a non-zero value to cause double stepping of
    the drive head ... useful when reading 40-track disks" -- and repeats
    the step when it is set.

DOS &4829 SELECT_DRIVE
    Take the drive from (IX+&0B), record it in DRIVE, and pick the port
    block: DISKCTL_0_BASE for one drive and DISKCTL_1_BASE for the other,
    chosen on the number rather than by two copies of the code.

DOS &4847 AT_SECTOR_LINK
    GRPNT, then return Z only when RPT has reached &01FE -- offset 510,
    where the two-byte link to the next sector sits.  The byte-at-a-time
    file code calls it to ask "is this sector's data used up?".  RPT is
    the pointer into the 512-byte sector buffer; nothing here is about
    pages.

DOS &4856 LDBLK
    Load a block from the open file to HL: the source's LDBLK, which
    HOOK_HLDBK falls into.  What is left of the current sector's data
    -- &01FE less RPT, 510 because the last two bytes are the link --
    is narrowed against what the caller still wants and copied with

    it is.  The source finished the tail a byte at a time; this build's

DOS &4E75 CHECK_FILE_TYPE
    The file type out of the header, masked to five bits and bounded: &15
    or more is "wrong file type", and &12 to &14 -- the three SAM types --
    are separated by SUB &12 with ADC A,&00, so one subtract and one add
    do the work of two comparisons.

DOS &4EE3 COPY_HEADER_FIELDS

DOS &4F67 FILL_DE_WITH_A

DOS &4F6C FILE_TYPE_AT_POINT

DOS &4F84 RESET_BUFFER_POINTERS
    Point IX at DOSBUF and BUF at DRAM, then fall into the pair below

DOS &4F8E CLEAR_TRANSFER_COUNT

DOS &4FBF GET_TRACK_AND_SECTOR

DOS &4FCD SWAP_TRACK_AND_SECTOR

DOS &4FD7 GET_FILE_NUMBER
    The entry's track and sector, as the number DIR prints against it.

DOS &4FF3 IS_END_OF_STATEMENT

DOS &51A7 PRINT_BYTE_AS_DECIMAL

DOS &56BB PRINT_DATE_IF_SET
    Fetch the &F5 buffer through GRPNTB, and return unless the first byte
    is set -- INC A then CP &02 rejects both &FF and &00 in one test.
    Otherwise "/" goes in C as the separator and the fields are printed
    in pairs.

DOS &56D0 PRINT_FIELDS_WITH_SEPARATORS
    Three fields and two separators: print, separator, print,
    separator, and then fall into PRINT_FIELD for the third.  The
    fall-through is what prints the year of a date and the minute of
    a time, and it is easy to miss because the routine looks as
    though it ends at the second separator.

DOS &56DE PRINT_FIELD
    One field as a decimal number through PNUM2 below, with HL, DE
    and BC all saved around it, so the caller's pointer survives.

DOS &5766 PRINT_A_KEEPING_IT
    Print A through the ROM and give it back unchanged.  PUSH AF round a
    CMR to PRINT_A, and it is the most-called routine of its kind in this
    half: everything that prints a character and then wants to look at it
    again goes through here.

DOS &576E PRINT_WORD_AND_SPACE
    Word B of the list at HL, then a space through SPC below.

DOS &5774 PRINT_WORD_B
    Step HL over B words, each ending at the character with bit 7 set,
    and then print the one it lands on.  The RLA is the test and the
    two jumps are the two loops -- inner over a word, outer over the
    count -- with no counter of its own; and when the DJNZ falls
    through, the &3E at &577B swallows PTM's POP HL so that execution
    runs on into PTM2, which prints the word now at HL and returns
    from PTM4.  That fall-through is how a type name or a compression
    code's text gets printed at all.

DOS &5815 PRINT_YN_PROMPT
    The tail of a confirmation prompt: a close quote, then compression
    code 4, which expands to " (y/n)".  Its one caller is PM7K, after
    FORMAT or FNM7K has printed a name in quotes.  Nothing here is a
    directory heading, whatever an earlier reading of it said.

DOS &597B EVAL_NAME_PAIR
    A filename, a separator that may be either a comma or TO, and a

DOS &5C1B PRINT_B_CHARACTERS

DOS &5C8B COLUMNS_FOR_DIRECTORY
    How many columns a directory listing gets.

    DCOLS if the user has fixed it.  Otherwise SYS_CHAR_WIDTH, read out
    of the system page, says whether CSIZE has magnified the character.

    THE &00 IS NOT A DISCARD, IT IS A PATCH SITE.  The AND A that tests
    the width is followed by LD A,&00, and that immediate at &5C98 is
    written from MasterBASIC's side: &65D0 puts the number of magnified
    characters that fit on a line into it, every time CSIZE runs.  So
    when characters have been widened the count below divides THAT, and
    a listing falls to one name a line only when fewer than twenty-one
    magnified characters fit -- two names need ten, a space and ten.

    With the width left alone the count comes from the window instead:
    WINDRHS gives the right and left edges, C minus B plus one is the
    width in characters, and the width plus one divided by eleven --
    ten for a name and one for the space after it, the last name on a
    line needing no space -- is the number of columns: three for the
    32-column window, where a plain division would give two.

DOS &6284 FETCH_STRING_IF_RUNNING

DOS &68DA PRINTABLE_FORM

DOS &6AEA CHANNEL_ENTRY_AT_ZERO_PAGE

DOS &6B77 RESET_CHANNEL_SCAN
    The same setup with IX instead of HL, and V4213 cleared first --

DOS &6CD6 SETLEN

DOS &6D30 CRMCH

    Neither branch returns at once and the table is laid down on both:

DOS &6D4F COPY_MTBLS

DOS &6F8D SAVE_BYTE_TO_FILE

DOS &6FC0 WRITE_AT_LINKED_SECTOR

DOS &6FCF SELECT_AND_READ_SECTOR

DOS &6FD5 CLEAR_SECTOR_FLAG

DOS &7003 ADVANCE_BUFFER_POINTER

DOS &7533 RDRSCT
    Read a sector from a RAM disc -- the author's own name, from the part
    of the source ref/masterdos/docs/ram-discs.md calls RAMD.  Every disk
    operation starts with TIRD, and for drives 3 to 7 it comes here
    instead of touching a controller at all.

    The shipped code has one thing the reference source does not.  There
    RDRSCT is CALL GTBUF then LD BC,&0200 straight into RDRS2; here

    round through DRAM; one that will not is read into the caller's

DOC RDRS2
    The copy itself, and it is an LDIR: RDADR works out where the sector
    lives in the RAM disc's pages, and &0200 bytes move from there to

DOS &46DF : the mask above was shifted for a rotated A and this bit number was not -- the source has AND &1C then BIT 4, RECORD NOT FOUND on an unrotated status; here AND &0E is that mask shifted, but BIT 4 of a rotated status is RECORD TYPE

# Every bit test on A that traces back to a port read was swept, in both
# halves, counting the rotates in between.  Only four sites apply a mask
# to a rotated status, and they are all in the DOS: &409D, &48E4 and
# &4A33, which are three copies of one seven-instruction loop and all
# read AND &0D; and &46C6, which reads AND &0E.  Everything else -- the
# page masks, the printer and serial tests, the BIT 1 that looks for DRQ
# at the head of each of those three loops -- is applied to the byte as
# read.  &46DF is not reachable by the sweep, because A gets there
# through PUSH AF and POP AF, but it is one rotate from a status read too.
#
# The three &0D are an error.  &0E is what the same question is asked with
# at &46C6, on a status rotated the same way, and &0E is the DOS source's
# own AND &1C shifted one place to suit that rotate.  &0D is that error
# set written for an unrotated status -- BUSY, LOST DATA, CRC ERROR -- so
# the shift was made at &46C6 and forgotten in the three loops.  As they
# stand they test CRC ERROR and RECORD NOT FOUND and cannot see LOST
# DATA, and the block load, the block save and the boot loader all reach
# CDE1 without ever passing through &46C6.
#
# Read as an ordinary mask &0D is BUSY, LOST DATA and CRC ERROR, so it
# looks as though it tests LOST DATA and misses RECORD NOT FOUND.  The
# rotate swaps those two round: RECORD NOT FOUND is tested, LOST DATA is
# not.  That is worth writing down because it is the natural misreading.
#
# Checked against SAMDOS (c:/repo/samdos/annotated-src), and it puts the
# error in MasterDOS rather than inherited.  SAMDOS never rotates: its
# transfer loops are unrolled -- in a,(c) / bit drq,a / jr nz, four times
# over -- and it tests BUSY with bit wd.st.busy,a, so A is always the
# status as read.  Its mask is a named constant,
#
#     wd.st.errors: equ %00011100  ; mask of lost data, CRC error and
#                                  ; record not found
#
# used at b.s:132 in the boot loader and c.s:453, c.s:933 and c.s:1160 --
# the same four places MasterDOS uses &0E and &0D.  So the intended set
# is not in doubt.
#
# MasterDOS rolled the loops up and replaced the BIT with RRCA, saving a
# byte and a few cycles in the tightest loop it has.  That rotate is what
# made a shifted mask necessary; %00011100 >> 1 is &0E, which &46C6 has
# and the three loops do not.
