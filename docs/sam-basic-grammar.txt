SAM BASIC / MasterDOS / MasterBASIC -- machine-readable grammar
==============================================================
FORMAT 1
COVERS  SAM Coupe ROM 3.0, MasterDOS 2.3, MasterBASIC 1.7

A translator between tokenised BASIC and text needs four things: the byte
layout of a program, the token table, the spacing LIST puts round a token,
and the syntax of each keyword.  All four are here.

Everything in [TOKENS], [SPACING] and [PRECEDENCE] is read out of the
sources rather than typed: KEYWTAB in ref/samrom/text.asm, OPPRIORT and
FNPRIORT in ref/samrom/eval.asm, and MBKEYS in the MasterBASIC page.
`python tools/tokentab.py --grammar` reproduces the [TOKENS] block exactly.

[STATEMENTS] and [FUNCTIONS] are not mechanical.  SAM BASIC has no
parameter table -- unlike the Spectrum, whose class bytes drive a generic
parser -- so each keyword's routine checks its own arguments, and the rules
there were read off those routines one at a time.  Every rule carries a `:`
line naming what it was read from.  A rule marked `?` is one the source did
not settle; treat it as the manual's claim and not as proven.  No rule in
this file carries one at present.

Companion documents:
  docs/tokens.md               the same tokens as prose, with the traps
  docs/masterbasic-tokens.md   how MasterBASIC gets a token at all
  docs/masterbasic-keywords.md what each MasterBASIC keyword does
  ref/masterdos/docs/          the same for MasterDOS


[NOTATION]
'X'          a literal: a keyword token, or a character
name         a rule defined in [RULES], [STATEMENTS] or [FUNCTIONS]
[ x ]        optional
{ x }        zero or more
( x | y )    grouping and alternation
x , y        in sequence
#8E          a token by code, where the name alone is ambiguous
--           to end of line, a comment

Line prefixes inside [STATEMENTS] and [FUNCTIONS]:
@ tok name   begins an entry; tok is the hex token, 2 or 4 digits
=            a production; several `=` lines are alternatives
> type       result type of a function: num or str
: text       provenance -- the file and routine the rule was read from
+ text       a note a parser writer needs
? text       something not established; the rule above it is unproven


[FILE]
A tokenised BASIC program is a run of lines, ended by a byte of &FF where
the next line number would start.

  line     := lineno-hi , lineno-lo , len-lo , len-hi , statements , &0D
  lineno   := 1 to 65279 (&FEFF), stored high byte first
  len      := bytes from the first byte of `statements` to the &0D
              inclusive, stored low byte first

Note the two byte orders: the line number is big-endian and the length
little-endian.  Line numbers ascend and do not repeat.

  statements := statement { ':' statement }

A numeric literal is stored twice.  The digits appear as typed, and are
followed by &0E and five bytes of the ROM's floating-point form:

  number   := digits , &0E , exponent , b1 , b2 , b3 , b4

exponent 0 marks the small-integer form: b1 is the sign (0 positive, &FF
negative), b2 and b3 the value low byte first, b4 zero.  Otherwise it is
sign-and-mantissa floating point, exponent biased by 128.  It is the five
bytes that get evaluated; the digits are only listed.  A translator that
rewrites a number must rewrite both.

Inside a string literal, and inside an INPUT LINE, bytes &80 and up are
graphics characters and not tokens -- "QUOTES FORCES UDGS", text.asm.
Outside quotes, &80 to &84 are still graphics characters, because no
token uses them.
: ref/samrom/tprint.asm PRGR80; ref/samrom/eval.asm INSERT5B


[LEXICAL]
How text becomes tokens, from TOKPT2 in ref/samrom/miscx2.asm.

- Matching is case-insensitive (XOR then AND &DF).
- A match is only tried where a letter, '<' or '>' starts a word.
- At most 15 characters are considered for one keyword.
- A keyword may contain a space: 'GO TO', 'DEF PROC', 'END IF', 'ON ERROR',
  'EXIT IF', 'LOOP IF', 'DEF KEYCODE', 'DEF FN', 'END PROC', 'GO SUB',
  'EXIT PROC', 'EXIT DO', 'EXIT FOR'.  One space in the stored name matches
  one space in the input.
- A match must not be followed by a letter, digit or underscore -- so
  PRINTER is a variable and not PRINT + ER.  The exception is a keyword
  ending in '=', '>' or '$': CHR$a is CHR$ followed by a.
- If a word starting with a letter matches nothing, the whole identifier
  (letters and underscores) is skipped before matching resumes.
- One space either side of the matched word is absorbed into the token.
- After REM the rest of the line is left alone.
- Inside double quotes nothing is tokenised; the scan resumes after the
  closing quote or at end of line.
- Keyword lists are searched in table order and the first match wins.  This
  is why IF is always stored as #D7 and ELSE as #D9 -- see [REWRITES].
- 'INK' matches the &FF entry and is stored as 'PEN' (&A1).  INK is an
  input spelling only and never appears in a file.
: ref/samrom/miscx2.asm TOKPT2, TOKMLP, POSFIRST, GTTOK, TOK42, LOOKNA

One editor feature reaches a line through the route a statement takes and
leaves no token behind.  Under MasterBASIC a '/' as the first non-space
character after a ':' splits the line there when RETURN is pressed: the
colon is overwritten with &0D, so the ROM enters everything before it as
the line, and the remainder stays in the edit area under a copy of the
original line number.  The '/' never appears in a stored program, so a
detokeniser never meets it, but a tokeniser handed such text must
reproduce the split rather than store the slash.  It arrives as CTAB's
first entry, token &2F -- ASCII '/', not the USING$ token that shares
the number.
: listings/clean/masterbasic.asm CMD_SPLIT_LINE


[REWRITES]
Two tokens are changed in the stored program after tokenising, by the
syntax-check pass rather than by the tokeniser.  A translator producing
tokens from text must apply both, or its output will differ from the
machine's for the same source text.

D7 -> D8   IF becomes short IF when a THEN follows the condition
D9 -> DA   ELSE becomes short ELSE when the IF it belongs to was short

Both pairs list identically, so the rewrite is invisible in a listing and
matters only byte for byte.
: ref/samrom/do.asm SIF (LD (HL),&D8), LELSE, IFTYPE


[SPACING]
What LIST puts round a token, from the `list-spacing` field in [TOKENS].

both    a space before and after
lead    a space before only
trail   a space after only
none    neither

Two further rules apply on top of the field:

- A leading space is printed only if the last character already printed was
  not a space (FLAGS bit 0).  So THEN GO TO gets one space between them and
  not two.
- A trailing space is printed only if the word's last character is a letter
  or '$'.  This never changes the outcome for the words in this table --
  the only names ending otherwise are '<>', '<=' and '>=', which are `none`
  anyway -- but a translator adding a keyword should know the rule.
: ref/samrom/tprint.asm POGEN2, POMSG4, POBTL, POMSP2, POTRNL


[PRECEDENCE]
Binary operators, from OPPRIORT in ref/samrom/eval.asm.  Higher binds
tighter.  All are left-associative; the ROM stacks an operator and only
executes it when the next one has priority less than or equal to it.

prec  operators
  2   'OR' 'BOR' <BXOR, &FF7D, no keyword>
  3   'AND' 'BAND'
  4   'NOT'                      -- unary, FNPRIORT
  5   '=' '<' '>' '<=' '>=' '<>'
  6   '+' '-'
  8   '*' '/'
  9   unary '-'                  -- NEGATE, FNPRIORT
 14   'MOD' 'DIV'
 15   '^'
 15   every other function       -- FNPRIORT default, "PRI. 16,N,N"

Two of these are worth stating plainly, because they differ from most
BASICs: MOD and DIV bind *tighter* than '*' and '/', and '^' binds tighter
still.  `a + b MOD c` is `a + (b MOD c)`; `2 * 3 MOD 2` is `2 * (3 MOD 2)`.

String operands take a different code for every comparison and for AND, so
`a$ AND b$` and `a$ + b$` are legal and yield strings, and the rest compare.
: ref/samrom/eval.asm OPPRIORT, FNPRIORT, PRIGRTR, SLOOP


[RULES]
Shared rules, referred to throughout [STATEMENTS] and [FUNCTIONS].

= letter      := 'A'..'Z' | 'a'..'z'
= digit       := '0'..'9'
= name        := letter , { letter | digit | '_' }
                 -- spaces inside a name are ignored by the ROM's matcher
= numvar      := name
= strvar      := name , '$'
= var         := numvar | strvar
= array       := ( numvar | strvar ) , '(' , subscripts , ')'
= subscripts  := numexpr , { ',' , numexpr } , [ ',' , slicer ]
= slicer      := [ numexpr ] , 'TO' , [ numexpr ]
               | numexpr
               | ''                 -- '()' is the whole string
= sliced      := strvar , '(' , slicer , ')'
= numexpr     := an expression yielding a number, per [PRECEDENCE]
= strexpr     := an expression yielding a string, per [PRECEDENCE]
= expr        := numexpr | strexpr
= lineno      := numexpr           -- evaluated, so GO TO n*10 is legal
= stream      := '#' , numexpr
: ref/samrom/lookvar.asm LOOKVARS; ref/samrom/assign.asm SLICING

Colour items.  Any of the six colour statements may appear as a modifier
inside PRINT, PLOT, DRAW, CIRCLE, FILL, PUT and INPUT.  Each takes one
number and each is followed by ',' or ';'.

= colour-item := ( 'PEN' | 'PAPER' | 'FLASH' | 'BRIGHT' | 'INVERSE'
                   | 'OVER' ) , numexpr
= colour-list := { colour-item , ( ',' | ';' ) }
: ref/samrom/misc1.asm CITEM, CITEMSR, INSISCSC

Print items and separators, shared by PRINT, LPRINT and INPUT.

= print-item  := 'TAB' , numexpr
               | 'AT' , numexpr , ',' , numexpr
               | colour-item
               | stream
               | expr
= print-sep   := ';' | ',' | '\''
                 -- ',' prints CHR$ 6, '\'' prints a carriage return
= print-end   := ')' | ':' | end-of-line
: ref/samrom/list.asm PRITEM, PRSEPR, PRTERM

The two-number and four-number forms named in the routines below.

= n2          := numexpr , ',' , numexpr
= n4          := numexpr , ',' , numexpr , ',' , numexpr , ',' , numexpr
= n-or-none   := [ numexpr ]       -- SYNTAX3: absent means 0
: ref/samrom/misc2.asm EXPT2NUMS, EXPT4NUMS, SYNTAX3

The block of program lines LIST and RENUM take, from BRKLSSL.

= line-range  := [ lineno ] , [ 'TO' , [ lineno ] ]
                 -- an absent first line is 1 and an absent last &FEFF, so
                 -- every part may be left out; a first line with no 'TO'
                 -- after it selects that one line, BRL1 copying FIRST to
                 -- LAST.  'LIST 10 TO' is legal and means 10 onwards.
: ref/samrom/misc2.asm BRKLSSL, BRL1, BRL2, BRL3

File names and drives, as MasterDOS parses them.

= filename    := strexpr
                 -- "d1:name", "d1:dir/name", "name"; drive 1-2 floppy,
                 -- 3-7 RAM disc, and every number goes through the alias
                 -- table at DVAR 111-117 before use
= pattern     := strexpr           -- '*' and '?' wildcards
: ref/masterdos/docs/commands.md; annotated-src CODN, TRX0

[STATEMENTS]
Every token that can begin a statement, in token order.  A statement that
begins with none of these is a procedure call:

= proc-call   := name , [ proc-args ]
= proc-args   := expr , { ',' , expr }
+ mainlp.asm reaches PROCS for any token below &90, which includes every
+ letter, so an unrecognised word at the start of a statement is a PROC
+ name and not an error until the PROC is looked for.
+ The separator is a comma and only a comma: PCSYL ends each argument
+ with INSISCOMA, which is the comma-only helper, not the INSISCSC that
+ takes either.  A semicolon between PROC arguments is a syntax error.
: ref/samrom/mainlp.asm ON4ENT (SUB &90 / JP C,PROCS); ref/samrom/fn.asm
: PCSYL; ref/samrom/misc2.asm INSISCOMA

@ 95 LOAD
= 'LOAD' , [ 'OVER' ] , filename , [ load-tail ]
= 'LOAD' , numexpr                          -- MasterDOS: by catalogue number
= load-tail := 'CODE' , [ numexpr , [ ',' , numexpr , [ ',' , numexpr ] ] ]
             | 'SCREEN$'
             | 'DATA' , ( numvar | strvar ) , '(' , ')'
+ The DOS only sees LOAD after the ROM's own syntax has failed, which is
+ how the by-number form arrives.
+ There is no UDG form.  The manual's LOAD "newset" CODE UDG CHR$ 128 is
+ an ordinary CODE address whose expression happens to be UDG CHR$ 128 --
+ HDR4 reads plain numbers after CODE and knows nothing of UDG.
+ LOAD and VERIFY accept one, two or three numbers, or none at all;
+ SAVE is the stricter case and needs at least two.
: ref/samrom/tapemn.asm SLMVC, HDR4, HDRNMS, HDRN1, HDRNOK;

[FUNCTIONS]
Every two-byte token that appears inside an expression, in token order.
`> num` or `> str` is the result type.  Argument types come from FNPRIORT
where the ROM records them and from the routine otherwise; a function not
listed in FNPRIORT takes one number and returns one, at priority 15.

The ROM divides these into three groups, and the group decides how the
argument is written:

  &FF3B-&FF52  immediate   no argument, a bracketed argument list, or #n
  &FF53-&FF79  fp calc     one argument, brackets optional
  &FF7A-&FF83  binary      an operator, not a function -- see [PRECEDENCE]

MasterDOS's and MasterBASIC's own functions, &FF26-&FF38, sit below all
three and each states its own form.
: ref/samrom/eval.asm IMFNATAB, FNPRIORT; ref/samrom/tprint.asm PSTFF2

[AUTOCOMPLETE]
What a completion list should offer, and where it should not.

- Offer statements only at the start of a statement: after a line number,
  after ':', after 'THEN', after 'ELSE', and after 'ON n:'.
- Offer functions and operators only inside an expression.
- Offer the qualifiers only where their statement allows them; they are
  never valid alone.  'TO' belongs to FOR, SAVE, DELETE, LIST, RENAME,
  COPY, MOVE, BACKUP, FORMAT, RECORD, JOIN, HIDE, ALTER and the ON forms
  of GO TO and GO SUB; 'STEP' to FOR, RENUM and LINE; 'THEN' to IF;
  'WHILE' and 'UNTIL' to DO and LOOP; 'AT' to PRINT, INPUT, EDIT, READ
  and WRITE; 'TAB' to PRINT and INPUT; 'USING' to FILL; 'OFF' to LINE,
  PROTECT, HIDE and RECORD SOUND; 'LINE' to SAVE, READ, INPUT, PALETTE,
  ALTER DISPLAY and RENUM; 'WRITE' is a statement, not a qualifier.
- Do not offer anything inside a string literal or after REM.
- Filter the list by what is loaded: the From column of [TOKENS] says
  whether a word needs MasterDOS or MasterBASIC.
- A name that is not a keyword at the start of a statement is a procedure
  call, so DEF PROC names belong in the statement completion list too.


[LIMITS]
Numbers a translator has to respect.

line number      1 to 65279 (&FEFF)
line length      the two-byte field allows 65535, but a line is built in
                 the edit buffer and is limited by free memory
statement depth  no limit in the format; ':' separates statements
keyword length   15 characters -- the tokeniser's LD BC,15
stream           0 to 16; 16 is output to a string
variable name    letters, digits and underscore; spaces inside a name are
                 ignored, so `my var` and `myvar` are the same variable
string length    16383 for SHIFT$; strings generally may exceed this
palette entry    0 to 15; colour 0 to 127
PALETTE LINE     174 down to -16, which is scan lines 1 to 191
palette changes  127 per screen; the LINICOLS list may not exceed &01FF
POKE values      31 numbers after the address
DEF KEYCODE      key codes 192 to 254 only
